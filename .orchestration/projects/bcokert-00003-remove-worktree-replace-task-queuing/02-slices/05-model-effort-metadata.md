# Slice 05 — Model/effort metadata on tasks and phases

**Goal:** Task files carry `model` and `effort` fields. Design interview and QA phases declare `model: opus, effort: max`. Implement reads and surfaces these when presenting each task.

## Happy path

- Task files generated by plan-project breakdown have `model` and `effort` fields with defaults `sonnet` / `default`.
- plan-project's design interview phase is annotated with `model: opus, effort: max`.
- QA phase (in implement or qa.md) is annotated with `model: opus, effort: max`.
- When implement presents a task, it surfaces the task's model/effort to the executing agent.

## Edge cases

- Old task files without `model`/`effort` fields: implement treats missing fields as `sonnet`/`default`.
- `agent_type` derivation in plan-project breakdown: unchanged.

## Files touched

- `defaults/commands/plan-project.md` — add `model`/`effort` fields to task file format template; annotate design interview phase header; add model/effort defaults to breakdown derivation rules
- `.claude/commands/plan-project.md` — sync from defaults
- `.orchestration/support/qa.md` — annotate with `model: opus, effort: max`
- `defaults/commands/implement.md` — surface task model/effort when presenting each task to the agent
- `.claude/commands/implement.md` — sync from defaults
